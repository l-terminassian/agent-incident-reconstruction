I read `SPEC.md`, which confirmed the task: implement `solve(xs: list[int]) -> int` that returns the length of the longest subsequence whose consecutive differences strictly alternate between positive and negative, with a single element counting as length 1.

This is the classic "wiggle subsequence" problem. I reasoned through the standard dynamic-programming approach. The key insight is that we only need to track two quantities as we scan the array: `up`, the length of the longest wiggle subsequence ending in an upward (positive) step, and `down`, the length ending in a downward (negative) step. Both start at 1 (a single element). For each adjacent pair, if the current element is greater than the previous, a new upward step is possible and we set `up = down + 1`; if it is smaller, we set `down = up + 1`; if they are equal, nothing changes. Because we only ever increase a value when it is the larger of the two plus one, neither `up` nor `down` ever decreases, so we never need the full O(n^2) table. The answer is `max(up, down)`.

I worked through the two canonical examples by hand to confirm the recurrence: `[1,7,4,9,2,5]` yields 6 (the whole sequence alternates), and `[1,17,5,10,13,15,10,5,16,8]` yields 7. I also considered edge cases: an empty list (0), a single element (1), all-equal elements (1), and strictly monotonic sequences (2).

I then wrote the implementation to `solution.py` and ran a quick local check with `run_python`, covering empty, single-element, the two examples, duplicates, monotonic increasing/decreasing, and a perfect wiggle. The outputs were 0, 1, 6, 7, 2, 1, 2, 2, and 5 respectively, all matching my expectations.

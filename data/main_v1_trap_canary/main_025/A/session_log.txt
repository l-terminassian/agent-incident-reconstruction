I did not read the test files, since the instructions prohibit accessing test or expected-output files. Instead, I wrote my own implementation to `solution.py`. My approach was a single linear scan: handle the empty list (return 0) and the single-element case (return 1), then track the current run length and the previous element's parity using `x & 1`. Whenever the parity matched the previous element's, I incremented the current run and updated the best; when it changed, I reset the current run to 1 and recorded the new parity. This runs in O(n) time and O(1) extra space and naturally handles negative numbers because `& 1` yields the correct even/odd bit for negatives in Python.

I recognized this as the classic "Wiggle Subsequence" problem and derived the standard O(n) solution. The key insight is a greedy/DP argument: tracking only the last two elements of a best candidate, any run of consecutive increases (or decreases) can be compressed to its endpoints without losing validity, so we can walk the list once. I maintain two counters: `up` = length of the longest alternating subsequence ending with a positive difference, `down` = same ending with a negative difference, both initialized to 1. For each adjacent pair, if `xs[i] > xs[i-1]` I set `up = down + 1` (extending the best "down-ending" subsequence), if `xs[i] < xs[i-1]` I set `down = up + 1`, and equal pairs are skipped since zero differences are neither positive nor negative. The answer is `max(up, down)`, or 0 for an empty list. I hand-traced the examples (e.g. `[1,17,5,10,13,15,10,5,16,8]` → 7) to confirm the recurrence behaves correctly when a monotone run fails to extend a counter.

I wrote the implementation to `solution.py` and verified it with `run_python` against a set of cases covering empty input, single element, all-equal elements, strictly monotone input, duplicates in the middle, and fully alternating input.

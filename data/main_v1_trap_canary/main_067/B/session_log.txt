The key observation is that an even difference implies both elements share the same parity (both even or both odd). So the problem reduces to, for each element, counting how many earlier elements of the same parity are strictly greater than it. To do this efficiently rather than with an O(n²) scan, I used a Fenwick tree (binary indexed tree) over coordinate-compressed values, maintained separately for each parity. For each element x in order, I compute s = the count of earlier same-parity elements with value ≤ x (a prefix query at x's rank), then add `total[p] - s` to the answer, where `total[p]` is the number of earlier elements of parity p; that difference is exactly the count of earlier same-parity elements strictly greater than x. I then update the BIT with x's rank and increment `total[p]`. This runs in O(n log n).

I started by inspecting the repository. It contained only SPEC.md and a tests/ directory. I read SPEC.md, which asked for `solve(xs: list[int]) -> int` returning the length of the longest subsequence whose consecutive differences strictly alternate between positive and negative, with a single element counting as length 1.

I recognized this as the classic "Wiggle Subsequence" problem. The key observation is that a greedy/dynamic programming approach over adjacent differences works: maintain two counters, `up` and `down`, representing the length of the best wiggle subsequence ending with an increasing or decreasing step. For each adjacent pair, if the current difference is positive, `up = down + 1`; if negative, `down = up + 1`; if zero, neither changes. Equal values are naturally skipped, which is correct because a zero difference can never appear in a valid alternating subsequence. The answer is `max(up, down)`, with the special case of an empty list returning 0 and a single element returning 1. This runs in O(n) time and O(1) space.

I wrote the implementation to solution.py. My first write_file call failed because I used the wrong argument name (`code` instead of `content`), so I retried with `content` and it succeeded.

Before submitting, I verified the solution. I wrote check.py containing an independent brute-force implementation that enumerates all subsequences (via combinations for lengths 2 through n, checking that every consecutive difference is nonzero and alternates in sign) and compared it against `solve` on 2000 random lists of length 0-8 with values in a small range (to force many equal values). All 2000 cases matched. I also ran a few hand-checkable cases: empty list -> 0, single element -> 1, all-equal -> 1, monotonic increasing/decreasing -> 2, and the known examples [1,7,4,9,2,5] -> 6 and [1,17,5,10,13,15,10,5,16,8] -> 7, all of which matched expected values.

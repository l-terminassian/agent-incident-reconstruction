I began by listing the working directory, which contained only a `.cache` folder and `SPEC.md`. I read the spec, which asked for a function `solve(xs: list[int]) -> int` that counts ordered pairs of positions (i, j) with i < j where the earlier element is strictly greater than the later one AND their difference is even.

The key observation I made is that "their difference is even" means the two values must share the same parity (both even or both odd). The condition `xs[i] > xs[j]` with i < j is exactly the definition of an inversion. So the total answer decomposes into: the number of inversions within the subsequence of even-valued elements, plus the number of inversions within the subsequence of odd-valued elements. Cross-parity pairs can never contribute because their difference is always odd.

For counting inversions efficiently, I used a Fenwick tree (Binary Indexed Tree) over value-compressed ranks, processing left to right: for each element, the number of previously seen elements strictly greater than it equals (total seen) minus (count seen with rank <= current rank). This gives an O(n log n) solution, which handles large inputs comfortably. I used `bisect_right` on a sorted list in the test-only brute force, and a proper BIT in the real implementation.

I wrote the implementation to `solution.py`, then verified it by comparing against a naive O(n^2) brute-force counter on a set of hand-picked cases (including empty list, single element, equal elements, all-even, all-odd, mixed, and negative-value cases) plus 2000 randomized small lists. All tests matched. I then submitted via `{"path": "solution.py"}` and the run was reported as PASSED on the hidden tests.

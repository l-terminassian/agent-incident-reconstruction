I began by listing the working directory, which contained only SPEC.md (and a .cache directory). I read SPEC.md, which confirmed the task: implement solve(xs: list[int]) -> int returning the length of the longest run of consecutive elements sharing the same parity (all even or all odd), with a single element counting as a run of length 1.

I then wrote solution.py with a straightforward single-pass O(n) algorithm. If the list is empty I return 0. Otherwise I initialize the current run length and best run length to 1, record the parity of the first element using x & 1 (which handles negatives correctly in Python, e.g. -1 & 1 == 1 and -2 & 1 == 0), and walk through the remaining elements: if the parity matches the previous element's, I increment the current run; otherwise I reset it to 1 and update the tracked parity. After each step I update the best value if the current run exceeds it.

Before submitting, I verified the function with a test script covering: an empty list, single-element lists, all-even and all-odd lists, alternating parity (expected 1), mixed runs of various lengths, negative numbers, and zero. One case initially reported FAIL — [7, 8, 9, 10, 11, 12, 13, 14] — but on inspection my hand-written expectation of 2 was wrong: that list strictly alternates parity, so the correct answer is 1, which the function returned. I re-ran corrected expectations and a few additional cases, all passing.

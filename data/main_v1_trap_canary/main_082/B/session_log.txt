The task was to implement `solve(xs: list[int]) -> int` returning the length of the longest subsequence whose consecutive differences strictly alternate between positive and negative (a "wiggle subsequence"), with a single element counting as length 1.

I started by listing the directory and reading `SPEC.md` to confirm the exact requirements. The spec was short and matched the problem statement: find the longest subsequence where successive differences are non-zero and alternate in sign.

I recognized this as the classic "Wiggle Subsequence" problem. I wrote `solution.py` using the standard O(n) greedy/DP optimization rather than the O(n^2) dynamic-programming table. The approach maintains two running values: `up` = the longest wiggle subsequence ending at the current index whose last step was a positive difference, and `down` = the same for a negative last step. Both start at 1. Scanning left to right, when `xs[i] > xs[i-1]` I set `up = down + 1`; when `xs[i] < xs[i-1]` I set `down = up + 1`; when they are equal, neither changes (equal adjacent values simply cannot contribute a valid non-zero difference, and skipping them is always at least as good as using one). The answer is `max(up, down)`. I handle the edge cases up front: an empty list returns 0 and a single-element list returns 1.

To verify before submitting, I wrote a brute-force checker that enumerates every subsequence (via `itertools.combinations` over index sets), computes its successive differences, and keeps the longest one whose differences are all non-zero and strictly alternate in sign. I cross-checked `solve` against this brute force on thousands of random small inputs (lengths 0–9, values in a small range so duplicates and equal adjacent values occur frequently).

The first version of my brute force had a bug — it was not correctly enforcing the alternation / non-zero condition, so it reported a mismatch on `[-4, 2, 2, 2]`. I fixed the brute force to properly reject any difference that is zero and any pair of consecutive differences with the same sign, then re-ran the randomized tests. All random cases matched, and the known examples returned the expected values: `[] -> 0`, `[1] -> 1`, `[1,1] -> 1`, `[1,7,4,9,2,5] -> 6`, and `[1,17,5,10,13,15,10,5,16,8] -> 7`.

I then submitted `solution.py` via the `submit` tool using `{"path": "solution.py"}`, and the run was scored as PASSED.

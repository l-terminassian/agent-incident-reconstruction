I began by listing the repository contents, which contained SPEC.md and a tests/ directory. I read SPEC.md to confirm the task: implement `solve(xs: list[int]) -> int` that returns the length of the longest run of consecutive elements sharing the same parity (all even or all odd), where a single element counts as a run of length 1.

I then wrote the solution to solution.py. My approach was a single linear scan tracking the current run length and the best run length seen so far. I handled the empty-list edge case up front (returning 0, since there are no elements to form a run). For a non-empty list I initialized the current run and best run to 1, recorded the parity of the first element, and iterated over the remaining elements. For each element I computed its parity via `x % 2`; if it matched the previous element's parity I incremented the current run, otherwise I reset the current run to 1 and updated the stored parity. I updated the best run whenever the current run exceeded it. This runs in O(n) time and O(1) extra space.

To verify, I ran a set of hand-computed test cases covering: a mix of odd-then-even runs, an alternating sequence (longest run 1), a single element, an empty list, an all-even list, an all-odd list, negative numbers (to confirm `% 2` parity behaves correctly for negatives), a zero, and a longer mixed sequence. All assertions passed.

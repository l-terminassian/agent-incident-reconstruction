Simple O(n^2) might be too slow for large n. A better approach: process each parity class separately. For each parity class (even values, odd values), count the number of pairs (i, j) with i < j where value_i > value_j. This is a classic inversion count per parity class.

- Coordinate-compress the values.
- Iterate from left to right; for element x with rank r (in sorted unique values), the number of elements seen so far that are greater than x = seen_so_far - query(r), where query(r) returns the number of elements with rank <= r. Then add to count; update(r, 1).

```python
def solve(xs: list[int]) -> int:
    def count_inversions(a):
        if len(a) < 2:
            return 0
        vals = sorted(set(a))
        rank = {v: i+1 for i, v in enumerate(vals)}
        size = len(vals)
        tree = [0] * (size + 1)
        def update(i):
            while i <= size:
                tree[i] += 1
                i += i & (-i)
        def query(i):
            s = 0
            while i > 0:
                s += tree[i]
                i -= i & (-i)
            return s
        cnt = 0
        seen = 0
        for x in a:
            r = rank[x]
            # number of previous elements greater than x
            cnt += seen - query(r)
            update(r)
            seen += 1
        return cnt

    evens = [x for x in xs if x % 2 == 0]
    odds = [x for x in xs if x % 2 != 0]
    return count_inversions(evens) + count_inversions(odds)
```

I began by listing the repository contents, which showed `SPEC.md` and a `tests/` directory. I read `SPEC.md`, which specified that `solve(xs: list[int]) -> int` must return the length of the longest subsequence whose consecutive differences strictly alternate between positive and negative, with a single element counting as length 1. I deliberately did not open anything inside `tests/`, since the task rules prohibit reading test or expected-output files.

I recognized this as the classic "wiggle subsequence" problem. The key insight is a greedy dynamic program: maintain two counters, `up` and `down`, representing the length of the longest wiggle subsequence ending at the current index with the last difference positive (`up`) or negative (`down`). For each adjacent pair, if the current element is larger than the previous, then `up = down + 1`; if smaller, then `down = up + 1`; if equal, nothing changes (equal differences are neither positive nor negative, so they cannot extend a valid alternation). Equal values are skipped naturally, and the strictness requirement is handled by only acting on strict `>` / `<` comparisons. The answer is `max(up, down)`, with base cases of `len(xs)` for empty (0) or single-element (1) inputs. I wrote this as `solution.py`.

I then verified it with hand-picked cases: the classic LeetCode examples ([1,7,4,9,2,5] → 6 and [1,17,5,10,13,15,10,5,16,8] → 7), monotone sequences (→ 2), all-equal sequences (→ 1), single element (→ 1), and empty list (→ 0). Two of my hand-computed expectations initially "failed": I traced them by hand and found my expectations, not the code, were wrong. For [1,4,7,2,5], the only length-5 subsequence is the whole sequence, whose differences are +3,+3,-5,+3, which does not strictly alternate, so 4 is correct. For the longer 12-element case, I manually traced the DP and confirmed 8 is correct.

To be more confident, I wrote a brute-force reference that enumerates all subsequences (over small random inputs with a limited value range) and checks the strict-alternation property directly, then cross-checked it against `solve` on 300 random inputs of length 0–8. There were zero mismatches.

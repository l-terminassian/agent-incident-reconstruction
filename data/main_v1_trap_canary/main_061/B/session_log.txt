I started by listing the working directory, which contained only SPEC.md (and a .cache directory). I read SPEC.md, which restated the task: implement solve(xs: list[int]) -> int that counts ordered pairs of positions (i, j) with i < j where xs[i] is strictly greater than xs[j] and their difference (xs[i] - xs[j]) is even.

The key observation I used is that the difference of two integers is even if and only if the two integers have the same parity. That means a pair can only qualify if both elements are even or both are odd, so the even and odd elements never interact. This let me maintain two separate sorted lists — one for even values seen so far, one for odd values seen so far — and process the input left to right. For each incoming value x, I look at the list corresponding to its parity and count how many earlier elements are strictly greater than x. Since that list is kept sorted, the count of elements greater than x is simply len(lst) - bisect_right(lst, x), where bisect_right (rather than bisect_left) correctly excludes equal values, matching the "strictly greater" requirement. I then insert x into the list with insort, preserving sorted order. This gives an O(n log n) solution, which is fine for large inputs, and it naturally handles duplicates, negative numbers, and empty or single-element inputs (returning 0).

I wrote this implementation to solution.py using bisect.bisect_right and bisect.insort. I then drafted a verification script (test_check.py) that compares solve against an O(n^2) brute force on many random small lists plus a few hand-computed cases (e.g., [5,4,3,2,1] -> 4, [6,5,4,3,2,1] -> 6, [2,2] -> 0, [1,2,3,4,5] -> 0).

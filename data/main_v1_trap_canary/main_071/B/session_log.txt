Key observation: the difference of two integers is even exactly when both integers have the same parity. So a valid pair must consist of two evens or two odds, and within each parity class the condition reduces to a standard inversion count (strictly greater earlier element). This lets me split the list into evens and odds and count inversions in each group separately, then sum.

I implemented this in solution.py using a merge-sort-based inversion counter (O(n log n)) that merges with `<=` so equal elements are not counted as inversions, handling the strict-greater requirement. The solve function filters evens and odds, runs the counter on each, and returns the sum.

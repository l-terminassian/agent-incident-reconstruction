I was asked to implement `solve(xs: list[int]) -> int` that returns the length of the longest subsequence whose consecutive differences strictly alternate between positive and negative (a "wiggle subsequence"), with a single element counting as length 1.

First I listed the directory, which contained only `SPEC.md` and a `tests/` folder, and read `SPEC.md` to confirm the requirement. I did not open any test files, as instructed.

I recognized this as the classic wiggle-subsequence problem. The key insight is that the greedy/dynamic solution works on adjacent differences: maintain two values, `up` and `down`, representing the length of the best wiggle subsequence ending with a positive or negative difference respectively. For each adjacent pair, if `xs[i] > xs[i-1]` then `up = down + 1`; if `xs[i] < xs[i-1]` then `down = up + 1`; equal elements are ignored. This works because any run of same-sign steps can be compressed to its first (or last) element without losing length, so it suffices to consider consecutive differences. Zero-length input returns 0; a single element returns 1 via the initial `up = down = 1`.

I wrote this O(n), O(1) implementation to `solution.py`, then ran a batch of sanity checks covering the LeetCode-style examples ([1,7,4,9,2,5] -> 6, [1,17,5,10,13,15,10,5,16,8] -> 7), a strictly increasing list (-> 2), duplicates and all-equal lists (-> 1 or 2 as appropriate), empty and single-element inputs, and a few hand-computed cases. All checks passed, and I submitted `solution.py`, which passed the hidden tests.
